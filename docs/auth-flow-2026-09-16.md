# Authentication flow repair

Implementation base: `origin/main` at `3f373b4`, fast-forwarded into `cambell/game-center`. Application changes remain local and undeployed. The hosted authentication audit and configuration changes below are tracked separately.

## Findings and changes

- Signup previously discarded the Supabase session result and called the application loader even when confirmation was still required. It now distinguishes a verified session from an unconfirmed user record.
- The root, staff invitation and player invitation share the same sign-in/signup/verification UI. A pending signup stays on verification; no profile write or protected application load is attempted before verification.
- `input-otp` 1.5.0 provides six code slots, numeric input, one-time-code autofill, paste normalization and native keyboard editing. Verification remains a real Supabase `verifyOtp({type: "email"})` operation.
- Sending, verifying and sign-in show busy indicators and reject duplicate submissions. Resends have a 60-second UI cooldown in addition to provider rate limits. Password/code values are cleared after completion.
- Recovery now uses `/auth/callback?next=/auth/reset-password` and a dedicated new-password form. Old browser recovery events also route to the reset screen.
- Callback destinations allow only the application root, password recovery and exact invitation paths; no arbitrary redirect is accepted. The current browser origin retains the PKCE cookie host, including `www` and approved previews.
- The initial app loader renders a CSS animation immediately, describes the actual loading phase, offers retry after a slow response, and fails to a recoverable error after 30 seconds. Generation checks discard stale loads. Reduced-motion preferences disable motion. Authentication read failures are caught rather than leaving hydration unfinished.
- Browser authentication HTTP requests have a 20-second abort deadline, preserve caller cancellation, and leave non-authentication data requests unchanged.
- There is no broad route Suspense fallback: it would turn some existing dynamic fixture 404 responses into streamed HTTP 200 responses. The root client loading UI is still rendered in initial server HTML.
